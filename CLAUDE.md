# Seedance Shorts Studio

Web UI lokal (Python stdlib saja, tanpa dependensi) untuk membuat klip YouTube Shorts lewat ComfyUI + node API Seedance (ByteDance). Seedance berjalan di cloud lewat API node ComfyUI (butuh login akun Comfy + kredit), bukan di GPU lokal.

## File
- `app.py` — server HTTP (port 7860, hanya 127.0.0.1). UI di `ui.html` (dibaca tiap request, `Cache-Control: no-store`). Proteksi: Host harus 127.0.0.1/localhost (anti DNS-rebinding) dan setiap POST wajib header `X-Studio: 1` (anti CSRF; tanpa ini situs lain bisa memicu generate berbayar/hapus file/ganti `comfy_cmd`). Job ComfyUI masuk antrean `WORK` dan dikerjakan **satu per satu** oleh thread `worker` (timeout dihitung saat job mulai). `GET /api/busy` dipakai supervisor sebelum update. **Semua panggilan ke ComfyUI lewat `LOCAL` (opener tanpa proxy)**: Python di Windows memakai proxy dari pengaturan Internet Windows (VPN/proxy) juga untuk `http://127.0.0.1` bila tidak ada di daftar pengecualian → ComfyUI dianggap mati padahal hidup (penyebab "ComfyUI ngga nyambung"; Ollama sudah lebih dulu begini). Unduhan internet (model, Pexels) tetap boleh lewat proxy. `comfy_url()` di-cache 3 dtk (satu thread mengecek, lainnya memakai hasil terakhir); URL yang pernah menjawab tetap dianggap hidup selama port-nya terbuka (ComfyUI sibuk = `/system_stats` lambat); scan PowerShell `running_comfy` maks tiap 120 dtk; `node_spec` juga menyimpan hasil "node tidak ada" 60 dtk. Bila belum tersambung, `/api/status` memberi `comfy_info` (`comfy_info()`: `state` dari `comfy.state.json` supervisor — starting/running/exited/crashloop/not_found/waiting, `nosup` bila file >30 dtk; `secs`, `code`, `retry`, `err` alasan dari `_find_comfy` (port tertutup / terbuka tapi tidak menjawab), `log` = 8 baris akhir `comfy.log`); UI `comfyWhy()` menampilkannya di banner + log di ⚙, tombol "Nyalakan ulang ComfyUI" → `POST /api/comfy/restart` (membuat `comfy.retry`). `/api/comfy/save` dengan port memanggil `_alive(url)` (dulu `_alive(port)` setelah ganti signature → port selalu ditolak). `/api/status` membaca ujung log saja (`log_tail(path,n)`), `has_tool` (which, cache 60 dtk), dan menyertakan `dl` (progres unduh model). **VRAM 8 GB**: `free_ollama()` (`/api/ps` + `keep_alive:0`) sebelum job workflow lokal; sebelum LLM, ComfyUI `/free` hanya bila `vram_free` < 6.5 GB. **Continuity antar klip (image-to-video)**: param generate `first_file` (file hasil; video → frame terakhirnya) atau `first_job` (take scene sebelumnya yang masih dibuat). `run_job` → `first_source()` (job dependensi masih queued/running → job dimasukkan lagi ke belakang `WORK`, stage "Menunggu scene sebelumnya"; dependensi hilang/gagal → error jelas) → `last_frame()` (ffmpeg `-sseof -0.6 … -update 1` → `cache/frames/<file>.last.png`) → `comfy_upload()` (multipart `POST /upload/image`, nama `studio_<file>`) → Seedance: `ByteDanceImageToVideoNode` (`I2V`; input `image` dari `LoadImage` node "3"; `node_spec(base, I2V)`; model tanpa versi i2v, mis. lite, diganti model i2v "fast") atau workflow lokal dengan `_studio.first_frame: [node, input]` (LoadImage node "900"; MiniMax H3 = node 6 `first_frame`). `job.first_used` (disimpan juga di meta) = take asal. `GET /api/lastframe?f=` = JPG kecil frame terakhir untuk UI. `/api/config` memberi `i2v`, `i2v_models`, dan `first_frame` per workflow. **Batal**: `POST /api/cancel {id | ids | all | llm}` → `cancel_job()`: job antre lokal → status `cancelled` (worker melewatinya); job di ComfyUI → `_stop_comfy()` (`/queue` delete bila belum jalan, `/interrupt {prompt_id}` HANYA bila job kita yang sedang `queue_running` — jangan mematikan pekerjaan aplikasi lain), loop polling tidur 0,25 dtk dan memeriksa `job.cancel` (`Cancelled`); render → `PROCS[id]` ffmpeg di-`kill`, cek juga saat ffprobe (`spec.cancelled`), file keluaran dihapus; LLM → `llm.CANCEL` memutus stream Ollama. Job yang menunggu job dibatalkan gagal dengan pesan jelas. Kredit Seedance cloud yang sudah terpakai tidak bisa ditarik kembali. UI: tombol ✕ Batal di `jobProg`, klik chip `#act` = batalkan semua (`cancelAll`), hapus take/scene/karakter/lokasi yang sedang diproses otomatis membatalkannya, `dropJobs`; `fix()` menangani status `cancelled`. **Gambar acuan (storyboard mirip Breakdown)**: param generate `refs` (file outputs: gambar karakter/lokasi Breakdown) + `seedream` (bool). `run_job` mengunggah acuan (`comfy_upload`, `ref_path`: untuk Seedream dibuat kanvas persegi 1024 letterbox putih di `cache/refs/<f>.sq.png` supaya bisa di-`ImageBatch` tanpa terpotong). Mesin: **Seedream** (`build_seedream`: `ByteDanceSeedreamNode` — node V1 dengan input statis; V3 memakai DynamicCombo — model `seedream-4-0-250828` (min 0,92 MP; 4.5/5.0 min 3,68 MP), `size_preset:"Custom"` + `seedream_size(aspek)` ≈2,4 MP sisi ≥1024, acuan digabung `ImageBatch` berantai, maks 10) atau workflow lokal dengan `_studio.refs: [[node, input IMAGE], …]` (`custom_graph`, LoadImage id `91k`; `qwen-image-edit-referensi.json` = Qwen-Image-Edit 2509 + Lightning, `TextEncodeQwenImageEditPlus` image1..3, belum diuji dengan ComfyUI asli). `/api/config`: `seedream`, `workflows[].refs`. Upload: `POST /api/upload?name=` (body mentah). Render: `POST /api/render` → `render.py` di thread, status lewat `JOBS`.
- **Progres (persen) semua proses**: job ComfyUI → `comfy_ws.py` (klien websocket stdlib ke `/ws?clientId=<job id>`, dibuka sebelum `/prompt`; event executing/progress/progress_state/execution_cached → persen berbobot: sampler & node API 20, loader 2, decode/save 1.5) di `job.progress {pct, stage, step}`, `job.started`/`elapsed`; antre lokal → "Antre ke-N" (dihitung di `GET /api/jobs`), antre di ComfyUI (dipakai aplikasi lain) → cek `/queue`. Render → ffmpeg `-progress pipe:1` (`out_time_us`/durasi). LLM → `/api/chat` streaming, `llm.PROG` (token / `est` per tugas, maks 95%), `GET /api/llm/progress`. Unduh model → `DL.index/count/overall`. Upload → XHR `upload.onprogress`. **Polling ringan**: `poll()` = `POST /api/jobs/query {ids}` (job yang ditunggu proyek ini, `waitIds()`, + job aktif; dulu `GET /api/jobs` 212 KB berisi semua riwayat tiap 2.5 dtk), dijadwalkan ulang sendiri (`pollSoon`): 2 dtk bila ada yang ditunggu/aktif, 6 dtk bila diam; `api()` memanggil `pollSoon` setelah `/api/generate`/`/api/render`; hasil diabaikan bila proyek berganti selama request. UI: `progHTML()` (persen + bar + waktu + sisa ~), `jobState()` membuat `<span class="js" data-job>` yang diperbarui di tempat (`updateJobSpans`, tanpa render ulang daftar video), chip `#act` di nav merangkum proses aktif. Job dianggap "hilang" hanya bila dibuat >2 dtk sebelum `poll()` mulai (`o.t`, `edit.mt/rt`) — dulu job yang dibuat bersamaan dengan poll salah ditandai hilang.
- `remote.py` — akses dari HP/laptop lain lewat **Tailscale**. `remote.kind(ip)`: 127.0.0.1/::1 = local (tanpa login); IP di `remote_nets` (default 100.64.0.0/10 + fd7a:115c:a1e0::/48) = remote, hanya bila `remote_access`; selain itu ditolak (Wi-Fi/internet). `host_ok`: Host remote harus IP literal, nama tanpa titik (MagicDNS) atau `*.ts.net`. PIN PBKDF2 (`remote_pin_salt/hash`), sesi = cookie HMAC dari `remote_secret` (HttpOnly, SameSite=Strict, 30 hari; ganti PIN = semua sesi batal), 5x salah = kunci 5 menit per IP. App bind `0.0.0.0` hanya bila `remote_access` + PIN ada (`BIND`); `POST /api/remote` (hanya dari PC) mengubahnya lalu `os._exit(3)` agar supervisor menyalakan ulang. `GET /api/remote` memberi info Tailscale (`tailscale status --json`) + URL. Halaman login `LOGIN_HTML` di app.py; `/api/login`, `/api/logout`. CLI: `python remote.py --set-pin X --enable`. `izinkan-akses-hp.bat/.ps1`: aturan firewall masuk khusus 100.64.0.0/10 di `app_port` + hapus aturan BLOKIR untuk python aplikasi (dibuat Windows bila prompt firewall dulu di-Cancel). Installer menawarkan Tailscale (winget) + PIN + firewall.
- `ui.html` — UI satu halaman, alur **linear** 6 tahap: 1 Ide → 2 Script → 3 Breakdown → 4 **Storyboard** → 5 Production → 6 Editing & Sound (tab id: idea, scr, bd, sb, prod, edit). Tombol "Lanjut" di tiap tahap menjalankan pekerjaan tahap berikutnya bila belum ada (storyline → script → breakdown; breakdown → storyboard → production). Pengaturan (ComfyUI, model workflow, Ollama, akses dari HP, API key, versi/update) di panel ⚙. Responsif: di bawah 820px satu kolom, nav dua baris (tahap; proyek + ⚙), input 16px (iOS tidak zoom). `api()` memuat ulang halaman bila 401 (sesi HP habis → halaman login). Semua data di `projects/<nama>.json` (v2): `dev, story, target, maxScene, scenes[] (duration, location, time, action, dialog, onscreen_text, visual, chars[], loc, props[], shot, angle, cam, dir, act, beat, …, board{job,img,error,own,ratio} (gambar storyboard), bprompt (override prompt gambar), prompt (override), takes[{job,file}], take, use, tin, tout, sub), look{style,camera,lighting,palette}, chars[{name,look,wardrobe,makeup,job,img}], locs[], props[], bd, imgwf, prod{engine,model,aspect,resolution,audio}, edit{tr,fade,ca,cv,sub,music,audios,mv,mwf,mp,mjob,rjob,final}`. `migrate()` mengubah proyek lama (panels/style). Kotak model (`MBOX`/`tabModels`) tampil langsung di tahap yang memakai workflow lokal (3 gambar `b-models`, 4 video `v-models`, 5 musik `e-models`); `needModels()` mengecek sebelum mengantre job (tidak ada lagi deretan kartu "Gagal: model belum ada"), progres unduhan disegarkan lewat `status()` selama `DLON`. Job dihubungkan ke item lewat id (sisi klien, `poll()`); prompt video = `compose()`: style + shot/angle/gerak kamera + kalimat sambungan dari shot sebelumnya menurut `transition_out` (`CARRY`: match on action, cut in, eyeline match, …) + frame awal + visual + arah gerak (`DIRTXT`) + frame akhir + karakter + setting + waktu (`todEN`: pagi→morning) + properti + cahaya bermotivasi + palet + `sounds()` (efek/atmosfer, sound bridge) + `speech()` (`Nama:` dialog, `Nama (OS):` di luar layar, `Nama (batin):` monolog interior, `VO/Narator:` narasi) + "no on-screen text". **Tahap 4 Storyboard** (`p-sb`, `sbRender`) — **acuan dari Breakdown**: mesin gambar sendiri `P.sbwf` (`sbEng()`: "" = Seedream cloud, selain itu file workflow; default Seedream bila ada API key, selain itu workflow bergambar acuan, lalu workflow gambar pertama), `sbCap()` = maks acuan (Seedream 10, workflow = `refs.length`, Z-Image 0), `boardRefs(sc)` = gambar karakter scene (`chars[].img`, berurutan) + lokasi (`sceneLoc`: `s.loc` atau cocok nama) dipotong sesuai kapasitas (lokasi diprioritaskan), prompt diawali "Use the reference images: image 1 shows the character … keep exactly the same face…" dan karakter/lokasi disebut "(image N)" bukan dideskripsikan ulang; `board.refs` mencatat acuan saat dibuat → peringatan "acuan di Breakdown berubah" (`sbRefsHTML`); checkbox `P.sbRefs`; peringatan merah bila mesin tanpa acuan; konfirmasi bila ada karakter/lokasi tanpa gambar di Breakdown; thumbnail acuan tampil di tiap panel. Selebihnya: grid panel berjajar (`.bgrid`, `--cols`; Otomatis = 4 untuk vertikal / 3 untuk lebar, pilihan "Per baris" 2–6 di `P.sbCols`), satu **gambar asli** per scene `s.board{job,img}` dibuat dengan workflow gambar (Z-Image) lewat `genBoard`/`boardPrompt` (gaya + "one single cinematic film frame, no panels/text" + ukuran shot & angle dalam kata (`SHOTIMG`/`ANGIMG`/`DIRIMG`) + `first_frame`/visual + karakter + setting + waktu + properti + cahaya/palet; boleh diedit per panel di `bprompt`), aspek = `P.prod.aspect` (select `sb-aspect` sinkron dengan `v-aspect`; `board.ratio` mencatat aspek saat dibuat → peringatan bila berbeda), tombol per panel Buat ulang / Upload gambar sendiri (`POST /api/upload`, `board.own`) / ✕, "Generate semua frame", panel memuat nomor, label babak berwarna (garis atas biru/oranye/hijau), ukuran shot, angle, durasi, aksi, dialog, kamera, transisi, suara, lokasi. Cetak/PDF: `window.print()` + `@media print` (A4 landscape, hanya `#p-sb`, kolom cetak 6 untuk vertikal / 3 untuk lebar, `inline-flex` agar mengalir antar halaman, judul proyek `.sbprint`). Breakdown (karakter/lokasi/pratinjau gaya) tetap memakai `imgWf()`/`P.imgwf` (select `b-imgwf`); Storyboard punya select `sb-imgwf` sendiri. Sketsa pensil di Breakdown dihapus (digantikan storyboard asli). **Tahap 5 Production — frame pertama** per scene (`s.start`: auto | board | prev | loc | none; **auto = gambar storyboard bila ada** → `first_file`, selain itu logika sambung scene sebelumnya; `startOf` memberi `src:"board"`; `take.from` = gambar storyboard yang dipakai → peringatan bila gambar diganti setelah take dibuat; prompt "The clip starts exactly on the given first frame, a storyboard still…"): `chainWanted(i)` = auto bila transisi scene sebelumnya `CHAIN_TR` (cut, match on action, cut in) dan lokasi sama (`locKey`), atau prev; `startOf(i)` → take terpilih scene sebelumnya (`first_file`), take yang sedang dibuat (`first_job`, jadi "Generate semua" bisa langsung mengantre seluruh rantai), gambar lokasi (loc), atau `missing`; `engFirst()` = mesin mendukung (Seedance: `cfg.i2v`; workflow: `first_frame`). `startInfo` menampilkan cuplikan frame + peringatan bila take terpilih tidak disambung dari take terpilih scene sebelumnya (`take.from` dari `job.first_used`). Prompt klip yang disambung: "The clip starts exactly on the given first frame…" (tanpa "Opening frame"). **Tahap 2 Script**: kartu scene berisi babak/beat, sebab-akibat (`link_in`, `purpose`), decoupage (shot · angle · kamera · arah), frame awal/akhir, suara, transisi; kepala babak + % (ideal 25/50/25), garis transisi antar kartu (`trLine`) (kepala babak dipakai di Script, Breakdown, Production, Editing; tidak di Storyboard); `contCheck()` = pemeriksa continuity tanpa AI (establishing shot di pembuka & lokasi baru — lokasi dibandingkan dari teks script, jump cut, lompatan ukuran ≥5 langkah, cut-in/match-on-action saat lokasi berganti, waktu berubah tanpa jembatan, arah gerak berbalik, eyeline/shot-reverse, sebab-akibat kosong, frame awal kosong, beat yang hilang, proporsi babak, ritme klimaks, scene terakhir bukan babak 3) → `#s-check` + `.cw` per kartu, diperbarui di `save()`; tombol "Perbaiki continuity (3 babak)" mengirim `contIssues()` ke tugas `continuity`. Field scene LLM `camera/direction` ↔ UI `cam/dir` lewat `fromLLM`/`toLLM`; `migrate()` menormalkan nilai lama (`OLDV`). Panduan ringkas di `<details class=guide>`. Editing: transisi "Ikuti script" (default) memakai `transition_out` per scene; musik ducking (`E.duck`, ffmpeg `sidechaincompress`).

- **Serial bersambung + cliffhanger** (tab "📺 Serial", `serTab/serRender`, folder `series/<nama>.json`, gitignored & dijaga updater; API `GET /api/series`, `GET/POST /api/serie`): serial = lapisan di atas proyek. Data serial: `name, logline, genre, tone, lang, target, voice, look, chars, locs, props, imgwf, sbwf, prod, bible (teks aturan tetap), total, episodes[{n,title,logline,events,arc,cliffhanger,project,final,summary,ledger}]`. "Jadikan serial dari proyek ini" menyalin look/karakter/lokasi/properti/prod; "Buat garis besar musim (AI)" = tugas LLM `season`. "Buat proyek episode" (`epMake`) membuat proyek `<Serial> E01` dengan karakter/lokasi/properti disalin dan `lock:true` (id & gambar referensi dipakai bersama; `makeBreakdown` tidak menimpa item terkunci dan mengirim `known` agar LLM memakai deskripsi persis), plus `P.series {name, ep, total, logline, bible, ledger, recap, outline, cliffhanger, finale, prevFinal}` yang dikirim ke tugas `storyline`/`script` (`llm._series_ctx` + `film.CLIFF`; storyline pakai `S_STORY_EP` dengan `recap`+`cliffhanger`; `fix_structure(series, recap)` memaksa scene pertama beat `recap` bila ada recap dan scene terakhir beat `cliffhanger` kecuali finale). `contCheck` meminta beat cliffhanger (bukan resolusi) di episode non-finale. "Buat ledger & ringkasan" (`epLedger`, tugas `ledger`) membaca proyek episode, menyimpan `summary` ("sebelumnya…"), keadaan tiap tokoh (status/kostum/bawaan/pengetahuan), hubungan, tempat-waktu, benang terbuka, cliffhanger, `final` (= `edit.final` episode) dan menambah karakter/lokasi baru ke bible; episode berikutnya hanya bisa dibuat setelah ledger episode sebelumnya ada. Frame pertama scene 1 bisa `prevep` (frame terakhir video final episode sebelumnya, via `first_file`). Beat baru `recap` & `cliffhanger` di `film.STORY_BEATS`. **Dunia bersama (world)**: serial = paket aset yang dipakai ulang; `worldFrom(P)` (look, chars/locs/props, imgwf, sbwf, prod, lang, styleThumbs, maxScene, sbCols, sbRefs, target, voice, `edit` {duck,tr,fade,ca,cv,sub,music,mv,mwf,mp}) ↔ `worldApply/worldSet(b,S)`; proyek terhubung lewat `P.world` (nama serial; terpisah dari `P.series` yang hanya untuk episode bersambung). "Cerita baru dari serial ini" (`storyMake`) = proyek lepas (tanpa cliffhanger/ledger) dengan semua aset sama, hanya ide/script baru. Di tab Ide proyek ber-`world` ada tombol ⬆ Simpan ke serial (`worldPush`: gabung per id, item baru ditambahkan) dan ⬇ Ambil dari serial (`worldPull`). `knownText()` memakai item `lock` bila `P.world`.
